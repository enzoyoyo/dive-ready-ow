# Contributing

Thank you for helping improve the template.

## Before opening a pull request

- Keep examples generic and free of names, locations, phone numbers, account identifiers and device paths.
- Add only media you created or are explicitly licensed to redistribute. Prefer a local, Git-ignored media workflow for personal course files.
- Do not weaken the safety boundaries: the app is a study aid, not an instructor, medical device or certification authority.
- Run the unit tests and review the diff for generated files, logs, signing material and large binaries.
- Update the catalog schema documentation when adding or changing fields.

Small, focused pull requests are easier to review. Explain any change that affects playback, accessibility, persistence or content provenance.
